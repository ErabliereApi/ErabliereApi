# Workflow — the vertical feature slice

The repeating unit of work in this repo. Git shows the shape: `feature/mcp-server-phase-4-plan-gating`,
`feature/744-AbonnementUserAccount`, `fix/code-scanning-gouvca-weather-s7044`. One branch walks the
stack from the entity down to the UI, then opens a PR.

Not every slice needs every step — a read-only endpoint skips the migration, an MCP tool skips the
UI. Walk the steps that apply, in this order, because each one's output is the next one's input.

## 1. Entity — `ErabliereModel/`

One type per file at the project root. Implement the right ownership marker from
`ErabliereModel/Ownable/` so authorization can find the owning érablière.

→ [conventions.md](../_shared/conventions.md)

## 2. Write DTOs — `ErabliereModel/Action/Post|Put|Patch/`

Scalar fields and FK ids only. **No navigation properties.** This is not a style preference; it is
the mechanism that makes step 4 safe.

→ **[write-endpoint-dto.md](../_shared/write-endpoint-dto.md) — read before writing the DTO**

## 3. Migration — `ErabliereApi/Depot/Sql/`

Entity configuration in `EntityConfiguration/`, then generate the migration. The `dotnet ef` command
and its prerequisite — `SQL_CONNEXION_STRING` and `USE_SQL` as **machine** environment variables,
because the ef tool ignores `launchSettings.json` — live in
[configuration.md § EF Core migrations](../_shared/configuration.md#ef-core-migrations).

→ also `ErabliereApi/Depot/Sql/Readme.md`

**Human check:** open the generated migration and read the `Up`. Autogenerated migrations pick up
unrelated pending model drift; delete what doesn't belong to this slice.

## 4. Controller — `ErabliereApi/Controllers/`

One controller per resource, French name. Bind the DTO from step 2 — never the entity. Apply
`ValiderOwnership("id")`, and validate every client-supplied FK belongs to the same érablière.
Register any new service in `ErabliereApi/Extensions/ServiceCollectionExtension.cs`, not inline in
`Startup.cs`.

→ [ErabliereApi/CLAUDE.md](../../ErabliereApi/CLAUDE.md)

## 5. Tests

At minimum a controller test in `ErabliereApi.Test`. Add an integration test in
`ErabliereApi.Integration.Test` when the slice crosses the pipeline (auth, OData, webhooks, ownership).
`WriteEndpointsBindDtoNotEntityTest` runs whether you remember it or not.

→ [testing.md](../_shared/testing.md)

## 6. UI — `ErabliereIU/`

New endpoint becomes a method on `src/core/erabliereapi.service.ts` (the single service wrapping all
backend calls), then the component. `npm run lint` must stay at **0 errors**.

→ `ErabliereIU/CLAUDE.md` — read it before touching the front-end

## 7. MCP tool — `ErabliereApi.Mcp/Tools/` *(only if the data is worth exposing to a model)*

The tool set is deliberately **curated**, not one tool per controller. A new tool has to earn its
place against the context it costs. Read-only, budgeted response envelope.

→ [ErabliereApi.Mcp/CLAUDE.md](../../ErabliereApi.Mcp/CLAUDE.md)

## 8. Proxy — `ErabliereAPI.Proxy/`

If external clients need the endpoint, regenerate with NSwag Studio (`GenerateProxy.ps1`). Never
hand-edit the generated files.

## 9. Verify and open the PR

```powershell
dotnet build ErabliereApi.sln
dotnet test
cd ErabliereIU; npm run lint      # if step 6 applied
```

Branch from `master`, name it `feature/<id>-<slug>` or `fix/<slug>`, PR into `master`.

## Where slices usually break

- A write endpoint bound the entity → the build fails at `WriteEndpointsBindDtoNotEntityTest`, and
  the fix is step 2, not an entry in `ExceptionsConnues`.
- The FK was validated for the root but not the children → ownership hole, no test failure.
  This is the tubelure bug.
- The migration carried unrelated model drift because nobody read the `Up`.
- An Angular component driven by MSAL events silently never renders — it needs
  `ChangeDetectionStrategy.Eager`.
